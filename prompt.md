=== 1. ПРОДАВЕЦ: страница "Заказы" — фильтр по датам и экспорт ===

Сейчас на странице заказов (и особенно на табе "Отменённые") только одно 
поле даты. Нужно заменить на диапазон дат (как у конкурента Dream Delivery — 
"Стартовая дата" + "Конечная дата"):

- Замени текущий одиночный date-input на два поля: "С какой даты" и "По какую 
  дату", фильтрация должна работать по диапазону created_at (или дате отмены 
  для таба "Отменённые").
- Добавь кнопку "Вывести в Excel" рядом со "Скачать накладные" в шапке — 
  экспорт текущего отфильтрованного списка заказов в .xlsx (можно использовать 
  библиотеку типа xlsx/sheetjs, если её ещё нет в проекте — добавь в 
  зависимости). Колонки: № заказа, телефон, адрес, стоимость, статус, дата.
- Примени этот же диапазон дат ко всем трём табам (Активные/Отменённые/Архив), 
  не только к одному.

=== 2. АДМИН: страница "Зоны" — не хватает инструмента рисования зон ===

Сейчас /admin/zones показывает карту с уже существующими зонами только для 
просмотра (полигоны отрисованы, но нет инструмента нарисовать новую зону 
или изменить форму существующей — только таблица снизу с переименованием/
удалением/привязкой курьера).

Найди компонент ZoneMapEditor — судя по всему, раньше он использовался на 
СТРАНИЦЕ ПРОДАВЦА (app/(seller)/delivery-zones/ или похоже) для рисования 
полигонов зон самим продавцом. Since we removed zone editing from seller — 
перенеси/подключи этот же компонент на страницу /admin/zones, чтобы админ мог:
- Рисовать новые полигоны зон прямо на карте (не только через таблицу)
- Редактировать форму существующих полигонов (перетаскивать вершины)
- Сохранять изменения в ту же таблицу zones, что уже используется

Если ZoneMapEditor всё ещё физически подключён на странице продавца — убери 
его оттуда (раз мы решили что продавец зоны не редактирует) и перенеси 
целиком на /admin/zones.

Проверь после правок: у продавца страницы /delivery-zones больше не должно 
быть в принципе (ни в меню, ни по прямому URL — см. пункт про защиту доступа 
из прошлого промпта), у админа на /admin/zones должен появиться реальный 
инструмент рисования на карте.

На странице карты продавца (скорее всего app/(seller)/orders-map/page.tsx 
или похожий путь — та же, что на скрине "Карта заказов") сейчас рисуются 
только точки заказов, зоны (полигоны) не подгружаются и не отображаются.

Компонент MapGL уже поддерживает пропс zones (массив полигонов) и рисует 
их через <Polygon> — это уже используется на карте курьера 
(app/(courier)/courier-map/page.tsx), возьми оттуда паттерн загрузки:

1. Добавь fetch зон продавца из таблицы zones, отфильтрованных по 
   seller_id = текущий продавец (courier.id аналог — тут это должен быть 
   id продавца из сессии/контекста продавца).

2. Сохрани результат в state (zones: MapZone[]) через useState, как это 
   сделано в courier-map/page.tsx.

3. Передай этот массив в <MapGL zones={zones} .../> — карта продавца 
   должна отобразить полигоны зон поверх точек заказов, ТОЛЬКО ДЛЯ 
   ПРОСМОТРА (без возможности редактировать/двигать вершины — это 
   остаётся только у админа).

4. Если у продавца несколько зон (несколько курьеров/районов) — покажи 
   все его зоны сразу, каждую своим цветом (цвет уже должен быть в 
   таблице zones, судя по структуре, которую видели в админке).
